# eepy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `eepy`, a single zsh script that keeps a MacBook awake with the lid closed while Claude Code sessions are active, and puts it to sleep safely afterwards.

**Architecture:** One executable zsh script, `eepy`, holds everything:

- pure decision functions: durations, triggers, hook transitions, hold and release decisions;
- thin readers around built-in macOS commands;
- the entry points: `run`, `hook`, `watchdog`, `setup` and `uninstall`.

The script can be sourced without running, so `test.zsh` sources it with every external command stubbed and asserts on the decisions. Claude Code hooks write one state file per session. The main loop reads those files every 30 seconds and treats the real `SleepDisabled` as the truth about holding. A user LaunchAgent runs the watchdog every minute.

**Tech Stack:** zsh (modules `zsh/system`, `zsh/datetime`), `pmset`, `ioreg`, `osascript` (JXA), `system_profiler`, `jq`, `ps`, `stat`, `visudo`, `install`, `launchctl`, `plutil`. Nothing to install.

**Spec:** `docs/superpowers/specs/2026-10-20-eepy-design.md`. Read it before any task. The use case numbers below refer to it.

## Global Constraints

- **Platform:** macOS 26, Apple Silicon. zsh only, built-in macOS commands only, nothing to install.
- **Two code files only:** `eepy` (the tool, executable) and `test.zsh` (the self-check).
- **Power changes:** every one goes through `sudo -n /usr/bin/pmset` with exactly one of three argument sets: `-a disablesleep 0`, `-a disablesleep 1` or `sleepnow`. Plain `sudo` (without `-n`) appears only in `setup` and `uninstall`.
- **Calling `sudo`:** always call it directly, never inside `$(...)`. When a FAILURE message needs its error text, send stderr to `$EEPY_HOME/err` and read that.
- **Calling `ps`:** always as `ps -o <field>= -p <pid>`, so the test stubs can intercept it.
  - Numbers from `ps` are left-padded, so compare them numerically.
  - Process start times always come from `proc_start <pid>`.
- **Time:** use `now` for the current time, never `$EPOCHSECONDS` directly.
- **Tests never touch real power settings.** `test.zsh` defines these stubs as shell functions: `sudo`, `pmset`, `ioreg`, `osascript`, `ps`, `launchctl`, `read_displays` and `now`. It aborts if the `sudo` stub is missing.
- **`eepy hook`** prints nothing to stdout and always returns 0. `log` writes only to the file unless `LOG_TTY=1`, which only `run` sets.
- **Defaults** (top of script, editable): `DEFAULT_FLOOR=20`, `DEFAULT_UNPLUG=0`, `DEFAULT_LOWPOWER=0`, `GRACE=120`, `INTERVAL=30`.
- **Safety constants** (top of script, commented as not to be changed): `THERMAL_MAX=2`, `TEMP_MAX=4000` (hundredths of °C), `CAP=3600`, `HEARTBEAT_MAX=90`, `HOPS=20`. The gap rule fires at more than `3*INTERVAL`.
- **Paths:**
  - `EEPY_HOME=${EEPY_HOME:-$HOME/.eepy}`, holding `sessions/`, `heartbeat`, `lock`, `err` and the hook temp files;
  - `EEPY_LOG=${EEPY_LOG:-$HOME/Library/Logs/eepy.log}`.

  The two environment overrides exist for tests only.
- **Log lines:** `YYYY-MM-DD HH:MM:SS <message>`. Stop reasons, attended-release reasons and anything unexpected start with `TRIGGER` or `FAILURE`.
- **User-facing text and log messages:** British English, no em dashes.
- **Tasks marked (owner)** change the real Mac, need its password or need the lid closed. The executor asks the owner before each such step and does it with them.
- **Git:** Task 2 initialises a git repo in the project folder. Each task ends with a commit.

## Review Focus

1. **Terminal tab closed while holding** (HUP, then writes to a dead terminal): eepy releases first and isn't killed by the broken output. Test `t_signal_release` in Task 8.
2. **eepy's idea of holding drifts from reality** (a failed release, the watchdog releasing while eepy hung, a stray hold at start). Holding follows the real `SleepDisabled` both ways and failed releases are retried. Tests `t_release_retry`, `t_reconcile_up`, `t_gap_after_watchdog` and `t_stop_retry` in Task 8.
3. **Hand-typed odd durations** (`90`, `0m`, `2H`, `1h30`, empty): rejected with the usage text, never treated as "no limit". Test `t_durations` in Task 2.
4. **`~/.claude/settings.json` missing, invalid, or already holding eepy hooks:** setup creates the file, aborts without touching it, or stays idempotent. Test `t_merge_hooks` in Task 10.
5. **Two `eepy` at once, or `uninstall` while one runs:** the second refuses and changes nothing. Tests `t_single_instance` in Task 8 and `t_uninstall_refuses` in Task 10.

### Task 2: Skeleton, test harness, arguments, logging

**Files:**
- Create: `eepy` (mode 755), `test.zsh`.

**Interfaces:**
- Produces:
  - `parse_duration <text>`: prints seconds, or returns 1. Valid input is `Nh`, `Nm` or `NhMm` (digits, lowercase units), with a total above 0.
  - `parse_args <args...>`: first resets `CMD=run`, `LIMIT=0` and `NOCLAUDE=0`, and copies `DEFAULT_FLOOR`, `DEFAULT_UNPLUG` and `DEFAULT_LOWPOWER` into `FLOOR`, `UNPLUG` and `LOWPOWER`. Then it reads the arguments: a command (`setup|uninstall|hook|watchdog`), one duration, `--no-claude`, `--battery N` (1 to 99), `--unplug` and `--low-power`. On anything else it prints `usage` to stderr and returns 1.
  - `usage`: prints the Commands block from the spec.
  - `now`: prints `$EPOCHSECONDS`.
  - `log <message...>`: appends `<date '+%F %T'> <message>` to `$EEPY_LOG`, creating its folder if needed. When `LOG_TTY=1` it also prints the line to stdout with `print ... 2>/dev/null || true`. It never uses a `tee` pipe.
  - `proc_start <pid>`: prints `LC_ALL=C ps -o lstart= -p <pid>` with runs of spaces squeezed and the ends trimmed, or nothing.
  - `main <args...>`: calls `parse_args`, dispatches on `CMD`, and exits with the command's status. After `hook` it always exits 0. Dispatch targets not built yet print "not built yet".
  - The script's last line is `[[ $ZSH_EVAL_CONTEXT == toplevel ]] && main "$@"`, so sourcing it only defines functions.
  - The harness in `test.zsh`:
    - `zsh test.zsh [t_name ...]` runs the named groups, or every `t_*` group in name order. Each group runs in a subshell that:
      1. exports a fresh `EEPY_HOME` (`mktemp -d`) and `EEPY_LOG=$EEPY_HOME/log`;
      2. sources `eepy` and defines the stubs;
      3. sets the default stub state;
      4. runs the group, then exits with its failure count.

      Any non-zero exit counts as a failed group. The harness prints `ok` or the FAIL lines, and exits non-zero if anything failed. `TEST_FILE` holds `test.zsh`'s absolute path.
    - `is <got> <want> <label>` prints `FAIL <group> <label>: got '<got>', want '<want>'` and counts the failure.
    - `typeset -gA PS_PPID PS_COMM PS_LSTART` is set at the top level.
    - Stubs, defined after sourcing `eepy`, so they override its functions:
      - `sudo`: when the arguments contain `-l`, it returns `${SUDO_L_RC:-0}` and records nothing. Otherwise it appends `$*` to the `CALLS` array and to `$EEPY_HOME/calls`. If `${SUDO_RC:-0}` is 0, it also sets `ROOT_OUT` to `"SleepDisabled" = Yes` for `disablesleep 1` or `= No` for `disablesleep 0`. It returns `${SUDO_RC:-0}`.
      - `ioreg`: prints `$LID_OUT`, `$BATT_OUT` or `$ROOT_OUT`, depending on whether its arguments mention `AppleClamshellState`, `AppleSmartBattery` or `IOPMrootDomain`.
      - `pmset`: prints `$PMSET_BATT` for `-g batt`.
      - `osascript`: prints `$OS_OUT`.
      - `ps -o <f>= -p <pid>`, real output shapes:
        - `ppid` is printed as `printf '%5s\n'`;
        - `comm` and `lstart` are printed verbatim, so tests can include trailing spaces;
        - an unknown pid prints nothing and returns 1.
      - `launchctl`: returns `${AGENT_RC:-0}`.
      - `read_displays`: prints `${DISPLAYS:-0}`.
      - `now`: prints `$NOW`.
    - Default stub state, which is also used in child mode:
      - lid open (`LID_OUT='"AppleClamshellState" = No'`);
      - `DISPLAYS=0`;
      - `ROOT_OUT='"SleepDisabled" = No'`;
      - `OS_OUT='0 0'`;
      - `BATT_OUT='"Temperature" = 3038'`;
      - `PMSET_BATT`: 57% on battery;
      - `CALLS=()`.
    - `zsh test.zsh child <args>` sources `eepy`, defines the stubs (but not `now`) and the default state, keeps the inherited `EEPY_HOME`, `EEPY_LOG`, `SUDO_L_RC` and `AGENT_RC`, then calls `main <args>`.

### Task 4: Triggers and decisions

**Files:**
- Modify: `eepy`, `test.zsh`.

**Interfaces:**
- Consumes: the reader outputs from Task 3, and the globals `FLOOR`, `UNPLUG` and `LOWPOWER`.
- Produces:
  - `trigger <thermal> <temp> <pct> <src> <lpm>`: prints one reason, or nothing. The first rule that matches wins:
    1. thermal, temp, pct or src is `?`, or lpm is `?` while `LOWPOWER=1`: `FAILURE <name> unreadable`. The names are `thermal pressure`, `battery temperature`, `battery level`, `power source` and `Low Power Mode`, checked in that order.
    2. thermal ≥ `THERMAL_MAX`: `TRIGGER heat: thermal pressure <n> (limit 2)`
    3. temp ≥ `TEMP_MAX`: `TRIGGER battery temperature <t/100 with 2 decimals>°C (limit 40.00°C)`
    4. src is `battery` and pct ≤ `FLOOR`: `TRIGGER battery <pct>% (floor <FLOOR>%)`
    5. `UNPLUG=1` and src is `battery`: `TRIGGER on battery (--unplug)`
    6. `LOWPOWER=1` and lpm is `1`: `TRIGGER Low Power Mode on (--low-power)`
  - `decide <holding> <attended> <want> <tripped> <gap> <timeup>`: every argument is 0 or 1. `gap` is only ever 1 when eepy was holding at the previous check. It prints one action; the first row that matches wins:

    ```
    timeup                                     -> stop
    gap && !attended                           -> stop
    holding && tripped && !attended            -> stop
    holding && tripped && attended             -> pause
    holding && !want                           -> release
    !holding && want && !tripped && attended   -> hold
    otherwise                                  -> stay
    ```

### Task 5: Hook

**Files:**
- Modify: `eepy`, `test.zsh`.

**Interfaces:**
- Consumes: `now`, `log`, `proc_start`, plus `CLAUDE_NAME` and `RUNNING_STATUSES` from Task 1, written as constants in `eepy`.
- Produces:
  - `hook_next <json> <current>`: prints `<state> <touch>`. State is `working`, `waiting`, `finished`, `rm` or `keep`; touch `1` means "refresh activity". It implements the spec's Session tracking table. Any event or tool not in the table gives `keep 0`.
  - `claude_pid <start_pid>`: walks up with `ps -o ppid=`, comparing numerically. It prints the first pid whose `ps -o comm=` basename (`${comm:t}`) equals `CLAUDE_NAME`. It stops with no output at pid 1 or below, when `ps` fails, or after `HOPS` steps.
  - `hook`:
    1. Reads stdin and takes `session_id`. If there is none, returns 0.
    2. Finds the pid with `claude_pid $PPID`. If there is none, logs `hook <id8>: no claude process found, ignored` and returns 0.
    3. Reads `$EEPY_HOME/sessions/<id>` if it exists, applies `hook_next`, and writes the result. Old activity is kept when touch is `0`, and `rm` deletes the file.
    4. Writes atomically: `mkdir -p` the sessions folder, write to `$EEPY_HOME/.tmp.<id>.$$` (outside `sessions/`), then `mv` it in.
    5. Logs `hook <first 8 chars of id> <old> -> <new> (<event>)` on any change, and `FAILURE hook <id8>: Stop without task info` when `Stop` lacks either array.

    It never prints to stdout, never calls `exit`, and always returns 0. zsh runs the last stage of a pipe in the current shell, and the tests call it there.
  - State files are `$EEPY_HOME/sessions/<session_id>`, 4 lines: state, activity (epoch seconds), pid, `proc_start <pid>`.

- [ ] **Step 1: Write the failing tests.**


### Task 8: The check loop

**Files:**
- Modify: `eepy`, `test.zsh`.

**Interfaces:**
- Consumes: Tasks 2 to 7.
- Produces:
  - Globals: `HOLDING` (0 or 1), `LAST_CHECK` and `LAST_ACTIVE` (epoch seconds, 0 at start), `END` (epoch seconds, 0 means no limit), `STOPPING` (a stop reason, empty until a stop is decided), `LAST_SUMMARY`.
  - `check_once`: one pass of the spec's Behaviour. It returns 0 to carry on, or 1 once eepy has stopped and released. In order:
    1. `t=$(now)`. Touch `$EEPY_HOME/heartbeat`.
    2. **Reconcile:** `prev=$HOLDING`, then `HOLDING=$(read_held)`. If they differ, log `FAILURE expected holding=<prev>, SleepDisabled says <HOLDING>; following SleepDisabled`.
    3. **A stop is in progress** (`STOPPING` is set): `release`. If `read_held` is now `0`, return 1; otherwise return 0, and the release is retried next check.
    4. `gap`: `prev=1` and `LAST_CHECK>0` and `t−LAST_CHECK > 3*INTERVAL`. Then set `LAST_CHECK=t`.
    5. **Read and work out:**
       - `attended=$(read_attended)`, `read_os`, `read_temp`, `read_batt`;
       - unless `NOCLAUDE=1`, `scan_sessions $t`;
       - `want`: `NOCLAUDE=1`; or `ACTIVE>0` (which also sets `LAST_ACTIVE=t`); or `LAST_ACTIVE>0` and `t−LAST_ACTIVE < GRACE`;
       - `timeup`: `END>0` and `t ≥ END`;
       - `reason=$(trigger …)`, and `tripped` if it is non-empty.
    6. **Act on** `decide $HOLDING $attended $want $tripped $gap $timeup`:
       - `hold`: `hold`, then `HOLDING=$(read_held)`.
       - `release`: log `released: no active sessions`, `release`, then `HOLDING=$(read_held)`.
       - `pause`: log `<reason> (attended: released, not sleeping)`, `release`, then `HOLDING=$(read_held)`.
       - `stop`: set `STOPPING` to the reason and log it. The reason is the trigger reason, `time limit reached` or `FAILURE gap: no check for <n>s while holding`. Then `release`, and `HOLDING=$(read_held)`. Return 1 if `HOLDING=0`, else 0.
    7. **Log the state:**
       - while `HOLDING=1`, log a readings line every check: `attended=<a> thermal=<t> temp=<x.xx>°C batt=<pct>% <src> lpm=<l> sessions: <REPORT>`;
       - otherwise, log `attended=<a> active=<ACTIVE>` only when it differs from `LAST_SUMMARY`.
  - `run`, in this order:
    1. `trap on_signal INT TERM HUP` and `trap '' TSTP PIPE`, before any output. Never set an EXIT trap.
    2. `mkdir -p $EEPY_HOME/sessions`, then `: >> $EEPY_HOME/lock`. `zsystem flock` does not create the file.
    3. Take the lock with `zsystem flock -t 0 -f lockfd $EEPY_HOME/lock`. If that fails, print `eepy is already running` to stderr and return 1.
    4. Check `sudo -k -n -l /usr/bin/pmset` with each of the three argument sets. If any fails, print `run "eepy setup" first` and return 1.
    5. Check `launchctl print gui/$UID/local.eepy.watchdog`. If it fails, print `the eepy watchdog is not loaded; run "eepy setup"` and return 1.
    6. Set `LOG_TTY=1`. Log a start line with every setting and safety constant. Set `END`.
    7. Set `HOLDING=$(read_held)`. If it is 1, log `FAILURE sleep was already disabled at start; taking it over`.
    8. Loop: `check_once || break; sleep $INTERVAL & wait $!`. Return 0 at the end.
  - `on_signal`, in this order: `trap '' INT TERM HUP`, `release`, log `stopped by signal`, `exit 0`.
